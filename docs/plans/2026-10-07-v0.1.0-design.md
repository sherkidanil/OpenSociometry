# OpenSociometry 0.1.0 — design

## Goal

Keep the existing OpenSociometry visual style while making the offline study workflow correspond to socialmatrix.net: create/find/copy a protocol, import a participant list or prefilled choices, edit positive/negative/perceptual choices, inspect a full group report and a participant report, work with sociograms, and export results. Data stays on the user's machine. `v0.0.2` is preserved as an immutable Git tag.

## Reference and boundaries

The reference site's help describes a one-column participant workbook in XLS/XLSX/CSV, protocol creation, choice editing, result printing, personal indices and mutual-choice sociograms. Its December 2025 update adds a workbook containing participants and choices. The signed-in account allowed inspecting an existing protocol and reports; demo restrictions blocked creating a new one, so the import format must be supported by a documented, flexible local parser rather than assuming an undocumented exact layout. Website accounts, payments, forum, cloud storage and registration are outside the offline program's domain.

Sources: https://socialmatrix.net/help/ ; https://socialmatrix.net/news/poyavilas-vozmozhnost-zagruzhat-fayl-s-uzhe-zapolnennymi-vyborami/ ; https://socialmatrix.net/socialmatrix/ (authenticated observation, 2026-10-07).

## Options considered

1. **Extend the existing standard-library app (chosen).** Keeps the current UI, local SQLite storage and double-click launchers. Requires careful migration and a small parser for each spreadsheet format.
2. Rebuild as Electron/Tauri. Could bundle a runtime, but adds installation and packaging complexity and changes the existing app substantially.
3. Wrap the website. Cannot meet offline storage and local operation.

## Architecture

The Python HTTP server remains bound to `127.0.0.1`; SQLite stores protocols, participants, criteria, selections and new optional metadata. A migration adds fields without changing current databases. The UI remains one static HTML/JS/CSS app; new actions are placed in its existing cards, tabs and graph controls. All writes use the existing JSON API or multipart file upload. Server-side validation is authoritative. Files in `data/` remain Git-ignored. No password or site data is stored in the repository.

## Data flow and behavior

- Protocols can be created empty, cloned, renamed, filtered and removed. Participants can be added, renamed, deleted and marked as filled; editing choices autosaves and the filled state follows the editor flow.
- Import accepts CSV, XLSX and legacy XLS. A one-column sheet imports participants. A matrix sheet has participant names in the first row and first column and marks (`+`, `-`, `1`, `-1`, words) in cells. It accepts an optional numbered first column and ignores a recognized heading row. An explicit choice-file mode removes ambiguity and permits import during protocol creation or later. Parse and validate the entire upload before changing the database so a bad file leaves the protocol untouched.
- Reports include the matrix, mutual positive/negative and paradoxical pairs, status groups using the reference site's published thresholds, individual and group indices, positive/negative and mutual sociograms, participant drill-down, print/PDF through the browser, CSV and local JSON backup. Graph layout actions save locally with the study.
- Optional participant photos stay local in `data/` or the database and appear on graphs. Exports include them when appropriate.

## Error handling and safety

Reject unsupported file types, corrupt spreadsheets, duplicate/ambiguous names, unknown matrix columns and oversized uploads with useful Russian messages. Check that all referenced IDs belong to the same protocol. Keep API access on loopback and prevent file traversal. Backups are versioned and validated before restoring. Preserve old databases via additive migration.

## Verification

Exercise parser fixtures for list/matrix XLSX, XLS and CSV, a populated protocol and malformed uploads; check calculations against hand-computed small groups and published formulas; exercise create/edit/restart/backup/restore through the HTTP API and the browser. Validate `start.command` and `start.bat` syntax/behavior where their operating systems are available, with macOS run verified directly and Windows checked by CI.
