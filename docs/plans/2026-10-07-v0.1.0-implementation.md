# OpenSociometry 0.1.0 Implementation Plan

**Goal:** Deliver the reference site's core sociometry workflow as an offline app with the existing visual style and reliable local storage.

**Architecture:** Extend the current Python standard-library HTTP server and SQLite schema. Add a small import module and new API operations; keep the static UI and extend its existing pages and controls. Validate and parse imports before database writes. Use versioned backup data.

**Tech Stack:** Python 3.8+, SQLite, HTML/CSS/vanilla JavaScript, `unittest`, GitHub Actions for Windows/macOS smoke checks.

---

### Task 1: Import compatibility

**Files:** `app.py`, `tests/test_imports.py`, `static/app.js`, `README.md`.

1. Write failing tests for one-column CSV/XLSX, numbered columns, matrix marks, malformed files, and atomicity.
2. Run `python3 -m unittest discover -s tests -v`; inspect the expected failures.
3. Implement normalized table parsing, matrix detection and validation, and import in one transaction. Add `.xls` via a documented bundled parser or optional conversion path with no runtime installation requirement.
4. Run the tests again. Add a file import mode and template download in the current setup controls.
5. Commit.

### Task 2: Protocol workflow and persistence

**Files:** `app.py`, `static/app.js`, `tests/test_workflow.py`.

1. Write failing API tests for copy, search fields, completed questionnaire state, and database restart.
2. Run tests and inspect failures.
3. Add additive SQLite migration, copy endpoint, filled state, API validation, and existing-UI controls.
4. Run API and browser smoke checks.
5. Commit.

### Task 3: Reports and calculations

**Files:** `app.py`, `static/app.js`, `static/style.css`, `tests/test_results.py`.

1. Write failing tests for published status bands, mutual/paradoxical pairs, individual and group indices, empty groups.
2. Run tests and inspect failures.
3. Implement calculations and report sections, individual drill-down and mutual-choice graph filtering in the existing style.
4. Run tests and browser checks of graph and report actions.
5. Commit.

### Task 4: Local media and export

**Files:** `app.py`, `static/app.js`, `static/style.css`, `tests/test_export.py`.

1. Write failing tests for optional photo upload and versioned backup/restore.
2. Run tests and inspect failures.
3. Implement local photo storage/rendering, export of sociograms, backup validation and print styling.
4. Run tests and browser smoke checks.
5. Commit.

### Task 5: Release verification

**Files:** `README.md`, `start.command`, `start.bat`, `.github/workflows/test.yml`, `VERSION`.

1. Document exact supported formats, local data path and launcher steps.
2. Run full `unittest`, syntax checks and local HTTP smoke test; exercise the UI in the real browser.
3. Add macOS/Windows CI smoke checks and verify CI state after pushing.
4. Review the diff against this plan and the reference workflow. Keep `v0.0.2` tag unchanged; push the v0.1.0 branch or merge when complete.
